تقرير HTML تفاعلي ثنائي اللغة

ملف واحد مستقل باللغتين العربية والإنجليزية مع تقييم عام، ألوان دلالية واضحة، فلترة فورية، وبحث مباشر بالملف والسطر.

المعايير الأكاديمية والصناعية

استكشف المعايير الـ 16 التي تقيسها الأداة

تغطي 6 أبعاد رئيسية في هندسة البرمجيات (CK · MOOD · QMOOD · Maintainability · Security · UML).

#1المستهدف ≤ 4

الاقتران بين الكائنات (CBO)

يقيس متوسط عدد الكلاسات التي يعتمد عليها كل كلاس لقياس استقلالية المكونات.

#2المستهدف 0 – 1

نقص التماسك في الدوال (LCOM)

يكشف الكلاسات الضخمة التي تؤدي مهاماً غير مترابطة (تعريف CK).

#3الأعلى أفضل

مؤشر إعادة الاستخدام (Reuse Index)

مؤشر QMOOD المركّب مع دعم المقارنة المرجعية عبر --baseline.

#40–100 · المستهدف ≥ 80

مؤشر قابلية الصيانة (MI)

يدمج حجم Halstead والتعقيد وعدد الأسطر والتعليقات لتقييم سهولة الصيانة.

#5المستهدف ≤ 5

التعقيد الدوري (CC)

يحسب عدد المسارات المتفرعة في كل دالة ويحدد أكثر الدوال تعقيداً.

#6لكل 1K SLOC · المستهدف 0

كثافة العيوب (Defect Density)

معدل الأنماط الخطرة والأخطاء البرمجية المكتشفة لكل 1,000 سطر كود.

#160–10 · المستهدف ≥ 8.5

جودة الأسلوب والقراءة (Style)

يقيم التسمية، طول الدوال والأسطر، عمق التداخل، والتوثيق لكل لغة.

#7المستهدف 0 – 3

عمق شجرة الوراثة (DIT)

متوسط مستويات الوراثة للكلاسات لضمان عدم تعقيد التسلسل الهرمي.

#8المستهدف 0 – 4

عدد الأبناء المباشرين (NOC)

متوسط الكلاسات الفرعية المباشرة لقياس نطاق تأثير التعديلات.

#90–1 · المستهدف ≥ 0.10

معامل تعدد الأشكال (PF)

نسبة الدوال المعاد تعريفها إلى الحد الأقصى الممكن وفق نموذج MOOD.

#10المستهدف ≥ 90%

التتبع الهيكلي (Class Diagram)

يتحقق من وجود الكلاسات والدوال والعلاقات المرسومة في class*.puml داخل الكود.

#11المستهدف ≥ 90%

المطابقة السلوكية (Sequence)

يتحقق من مطابقة استدعاءات مخطط التسلسل seq*.puml مع الاستدعاءات الفعلية.

#12المستهدف ≥ 90%

تغطية حالات الاستخدام

يربط حالات الاستخدام في usecases.txt مع الكلاسات والدوال المنفّذة.

#130–10 · المستهدف ≥ 9

الامتثال المعماري

يكشف انتهاكات الاعتماد بين الطبقات وفق قواعد architecture.json.

#14المستهدف = 0

الثغرات الأمنية (Security)

يرصد حقن SQL، eval، التشفير الضعيف، تعطيل TLS، والمفاتيح المكشوفة.

#15المستهدف ≥ 80%

تغطية الاختبارات (Coverage)

يقرأ تلقائياً تقارير JaCoCo و lcov و Cobertura دون تنفيذ أي كود خطر.

دليل سريع

كيف تستخدم OODM في مشروعك؟

افتح الطرفية (Terminal) داخل مجلد مشروعك ونفذ أمراً واحداً فقط.

يفحص المجلد الحالي ويولّد ملف التقرير التفاعلي oodm-report.html تلقائياً:

# Scan current project folder
npx oodm-cli@latest

# Scan a specific project path
npx oodm-cli@latest ./path/to/project

# Skip missing documentation warnings
npx oodm-cli@latest --no-docstring-check

اختر الصيغة الأنسب لسير عملك (جدول طرفية، HTML، JSON، Markdown، أو CSV):

# Print summary table + worst offenders in terminal
npx oodm-cli@latest --format table --details

# Save HTML dashboard to a custom path
npx oodm-cli@latest --format html --out quality-report.html

# Export machine-readable JSON or Markdown
npx oodm-cli@latest --format json --out report.json
npx oodm-cli@latest --format md --out QUALITY.md

تكتشف الأداة الملفات تلقائياً في الجذر أو مجلد ./docs، أو يمكنك تمريرها يدوياً:

npx oodm-cli@latest \
  --class-diagram docs/class.puml \
  --sequence docs/seq.puml \
  --usecases docs/usecases.txt \
  --arch architecture.json \
  --coverage-report coverage/lcov.info

احفظ نسخة JSON مرجعية لإصدار سابق لقياس تحسن مؤشر Reuse Index مع تطور مشروعك:

# Step 1: Save baseline snapshot
npx oodm-cli@latest --format json --out baseline.json

# Step 2: Compare after refactoring
npx oodm-cli@latest --baseline baseline.json
